## Задание 2. Модель данных и создание задачи

Модель задачи: `{ id, title, completed, priority }`.

- `id` — положительное безопасное целое (`Number.isSafeInteger(id) && id > 0`).
- `title` — строка, после `trim()` длиной от 1 до 100 символов.
- `completed` — логическое значение, при создании всегда `false`.
- `priority` — `"low" | "medium" | "high"`, по умолчанию `"medium"`.

Ожидаемые ошибки возвращаются как данные `{ ok: false, error: "..." }`, а не бросаются как исключения.

## Распределение ответственности между файлами

- `data.js` — только исходные данные и номер варианта. Никакой логики.
- `task-service.js` — девять прикладных функций и внутренние помощники. Без `console.log`, без DOM, без глобального изменяемого списка.
- `main.js` — импорт модулей, последовательность действий, вывод и обработка отказов.
- `checks.js` — сравнение фактических результатов с ожидаемыми через `node:assert/strict`.
- `examples/functions-and-references.js` — учебные эксперименты по заданию 1.

## Вывод

Освоены: объявление и вызов функций, стрелочные функции, параметры по умолчанию, объекты и деструктуризация, spread и поверхностное копирование, методы массивов `find`, `filter`, `map`, контракты функций через объект результата `{ ok, ... }`, разделение кода на ES-модули и запуск модульного проекта через Node.js. Наиболее показательным оказалось поведение spread при копировании массива объектов: новый массив создаётся, но вложенные объекты остаются общими, что требует создания нового объекта при каждом изменении записи.

## 5. Защита от устаревших ответов и гонок

Эффект загрузки:

useEffect(() => {
  let active = true;
  const controller = new AbortController();
  setStatus('loading');
  setError(null);
  async function load() {
    try {
      const data = await api.loadInitialData(
        { q, completed, priority, categoryId },
        { signal: controller.signal },
      );
      if (!active) return;
      setSnapshot({ tasks: data.tasks, categories: data.categories, meta: data.meta });
      setStatus('ready');
    } catch (cause) {
      if (!active || controller.signal.aborted) return;
      setError(cause);
      setStatus('error');
    }
  }
  void load();
  return () => { active = false; controller.abort(); };
}, [api, q, completed, priority, categoryId, revision]);

Зависимости: api, q, completed, priority, categoryId, revision. snapshot и tasks в них не входят — они результат, а не вход.

Флаг active проверяется в обеих ветках — и в успехе, и в ошибке. Одной отмены недостаточно: источник может завершить запрос, не отреагировав на signal.

## 6. Защита от повторной мутации

Функция mutate:

- проверяет mountedRef и mutationRef; если мутация уже идёт — false;
- создаёт контроллер и сразу сохраняет в mutationRef до первого await;
- ставит pending: true и очищает mutationError;
- при успехе увеличивает revision и возвращает true;
- в catch сохраняет mutationError и возвращает false;
- в finally освобождает контроллер, только если он всё ещё «свой».

Ошибки загрузки и изменения разделены: error — GET, mutationError — POST/PATCH/DELETE. Успешный POST не становится ошибкой при неуспешном GET.

## 11. Ответы на контрольные вопросы

**Почему после успешной мутации выполняется повторный GET, а не локальное обновление?** Сервер — единственный источник истины. Повторный GET с текущими фильтрами показывает ровно то состояние, которое подтвердил сервер, включая назначенный id и completed.

**Зачем нужен флаг active, если запрос уже отменён?** AbortController — сигнал, а не гарантия немедленного завершения. Тестовый API или кэш может вернуть результат после abort. Флаг active отбрасывает такой результат.

**Чем error отличается от mutationError?** error — ошибка GET, снимок данных при этом сохраняется. mutationError — ошибка записи. Успешный POST не превращается в mutationError, если последующий GET упал.

**Почему блокировка мутации сделана через ref, а не через state?** setPending(true) асинхронно: два синхронных вызова saveTask могут увидеть старое pending и запустить две операции. Ref устанавливается до первого await и блокирует второй вызов сразу.

**Почему нельзя использовать общий контроллер для чтения и мутации?** Смена фильтра отменяет чтение, но не должна отменять сохранение. Иначе при быстром изменении фильтра POST обрывается, хотя сервер уже мог его принять.

**Почему «Всего задач в системе» — некорректная надпись для meta.total?** meta.total — число задач после серверных фильтров, а не размер всей базы. В интерфейсе используется формулировка «В последней полученной выборке».

**Почему при успешном POST и неуспешном GET запись не повторяется?** POST уже подтверждён. Повтор создал бы дубликат. Показываются отдельно успешное сохранение и ошибка обновления.

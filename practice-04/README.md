## 2. Эксперименты с формой и JSON

Страница: `examples/forms-storage.html`.

### Эксперимент 1. Пустое обязательное название

- **Прогноз:** браузер заблокирует отправку, обработчик `submit` не вызовется.
- **Факт:** журнал не изменился; `form.checkValidity()` → `false`; показано стандартное сообщение браузера.
- **Объяснение:** нативная валидация `required` срабатывает до события `submit`. Это не ошибка страницы, а штатное поведение HTML Constraint Validation.

### Эксперимент 2. Название из пробелов

- **Прогноз:** `required` пропустит строку из пробелов, прикладная проверка должна отклонить.
- **Факт:** отправка проходит нативный уровень; после `setCustomValidity("Название не может быть пустым")` поле становится невалидным; после исправления и `setCustomValidity("")` — снова валидно.
- **Объяснение:** HTML не знает про `trim`. Прикладное правило должно отдельно проверять нормализованное значение.

### Эксперимент 3. Сохранение корректных значений

- **Прогноз:** значения из `FormData` придут строками; `event.defaultPrevented` = `true`.
- **Факт:** `formData.get("id")` — строка `"20"`; `typeof` → `"string"`. После `Number(...)` — число. Название нормализовано через `trim`.
- **Объяснение:** `FormData` не приводит типы. Граница преобразования — явная (`Number`).

### Эксперимент 4. Чтение сохранённого значения

- **Прогноз:** `getItem` вернёт строку JSON.
- **Факт:** `typeof raw` → `"string"`; `JSON.parse(raw)` → массив объектов.
- **Объяснение:** `localStorage` хранит только строки. Для объектов — `JSON.stringify` / `JSON.parse`.

### Эксперимент 5. Повреждённый JSON

- **Прогноз:** `JSON.parse("{broken-json")` бросит `SyntaxError`.
- **Факт:** исключение перехвачено `try/catch`; приложение получило `{ ok: false, error }` и исходный набор.
- **Объяснение:** успешный `parse` подтверждает только синтаксис, но не схему. Нужны обе проверки: синтаксис и структура.

## 7. Восстановление и ошибки storage

- При загрузке `loadTasks` различает три источника:
  - `initial` — ключа нет, используется исходный набор;
  - `storage` — валидная запись, восстановлена из `localStorage`;
  - `fallback` — ошибка чтения/JSON/версии/схемы, возвращён исходный набор и текст ошибки.
- `saveTasks` сначала проверяет список, затем пишет `{ version: 1, tasks }`.
- Если запись невозможна (исключение), изменение остаётся в памяти вкладки, пользователь получает предупреждение.
- `removeSavedTasks` удаляет ровно один ключ. `localStorage.clear()` не используется.
- Повреждённая запись автоматически не удаляется — её можно исследовать в DevTools и сбросить кнопкой.

## 10. Отладка

Точка останова установлена в `handleFormSubmit` (`src/main.js`).

### 10.1. Успешный сценарий добавления (id = 20, «Изучить localStorage», high)

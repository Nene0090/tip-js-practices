## Задание 3. Делегирование, изменение статуса и удаление

Обработчик `handleTaskListClick` назначен на `ul#task-list` один раз при инициализации. Порядок работы:

1. Проверка `event.target instanceof Element`.
2. Поиск ближайшей кнопки через `closest("button[data-action]")` и проверка `listElement.contains(button)`.
3. Допустимы только `toggle` и `delete`. Клик по заголовку или пустому месту игнорируется.
4. Чтение `li[data-task-id]`, `Number(...)`, проверка `Number.isSafeInteger(id) && id > 0`.
5. Для `toggle`: `findTaskById` → текущий `completed` → `setTaskCompleted(currentTasks, id, !task.completed)`.
6. Для `delete`: `removeTask(currentTasks, id)`.
7. При отказе — сообщение в `#operation-message` через `textContent`, массив не меняется.
8. При успехе — `currentTasks = result.tasks`, очистка сообщения, `renderApp()`, `restoreTaskFocus(id, action)`.

Проверки:
- клик по вложенному `span.action-label` внутри кнопки — действие срабатывает (за счёт `closest`);
- двойное последовательное переключение id=4 возвращает исходное состояние;
- клик по заголовку и по пустому месту не изменяет данные;
- неизвестный `data-action` игнорируется;
- изменённый через DevTools `data-task-id="777"` и `"4abc"` не приводят к изменению данных, выводится сообщение об ошибке;
- удаление через `removeTask`, а не через `element.remove()`.

## Задание 4. Фильтры, сводка и пустые состояния

`getVisibleTasks(tasks, filter)` в `task-selectors.js`:
- `"all"` → копия массива (`tasks.slice()`);
- `"pending"` → `filter(t => t.completed === false)`;
- `"completed"` → `filter(t => t.completed === true)`;
- неизвестное значение → копия массива (не падает).

`handleFilterClick` через `closest("button[data-filter]")` распознаёт фильтр, меняет только `currentFilter`, очищает сообщение и вызывает `renderApp()`.

Активному фильтру выставляются `is-active` и `aria-pressed="true"`, у остальных — снятие.

`renderSummary` использует `getTaskStats(currentTasks)` для полного массива, а не подсчёт карточек в DOM. Значения:
- `[data-stat="total"]` — всего;
- `[data-stat="completed"]` — выполнено;
- `[data-stat="pending"]` — осталось;
- `[data-stat="progress"]` — прогресс всего списка с одним знаком после точки, для пустого списка `0.0%`;
- `[data-stat="visible"]` — длина видимой выборки.

При выборе «В работе» общий прогресс не становится нулевым — меняется только видимость.

`renderEmptyState(messageElement, total, visibleCount)`:
- `visibleCount > 0` → текст пустой, `hidden = true`;
- `total === 0` → «Список задач пуст.», `hidden = false`;
- `total > 0 && visibleCount === 0` → «Нет задач по выбранному фильтру.», `hidden = false`.

Пустое сообщение находится в отдельном `<p id="empty-message">`, не вставляется в список как карточка.

## Отладка

- Точка останова поставлена в `src/main.js`, в `handleTaskListClick`, на строке `const id = Number(card.dataset.taskId);`.
- До преобразования: `card.dataset.taskId === "4"`, тип `string`.
- После преобразования: `id === 4`, тип `number`.
- Выбранное действие (`button.dataset.action`) — `"toggle"`.
- Найденная запись (`findTaskById(currentTasks, 4)`) — `{ id: 4, title: "Подготовить модель задач", completed: false, priority: "high" }`.
- Результат `setTaskCompleted(currentTasks, 4, true)` — `{ ok: true, tasks: [...] }`, длина массива не изменилась, у записи id = 4 `completed === true`.
- После `renderApp()` в `#task-list` осталось 4 карточки, сводка обновлена на 3/1.

## Вывод

Освоены: выбор и создание DOM-элементов, безопасный вывод текста через `textContent`, `classList` и `hidden`, обработка событий через `addEventListener`, делегирование через `closest`, распознавание `dataset.taskId`, разделение данных, выборки и отображения, повторная отрисовка через `replaceChildren` без дублирования, сводка и пустые состояния, возврат фокуса после перерисовки. Прикладная логика ПР2 переиспользована без изменений.

Наиболее показательным оказалось различие между событием, которое всплывает, и обработчиком контейнера: без `closest` проверка только `event.target.dataset.action` не срабатывала бы при нажатии на вложенный `span`. Также важным было разделение `currentTasks` и видимой выборки: удаление карточки через DOM не считается удалением задачи, если массив не обновлён через сервис.
